# ⭐ S3 Object Lambda

**S3 Object Lambda** lets you run a **Lambda function** to transform data **on the fly** when an object is requested from Amazon S3—**without modifying the original object** stored in the bucket.

When a client performs **`GetObject`**, **`HeadObject`**, or **`ListObjects`** through a **special Object Lambda Access Point**, S3 invokes your Lambda function to process the request.

The Lambda function:

* Accesses the original object using a **pre-signed URL**
* Applies transformation logic
* Returns the transformed data to the requester using **`WriteGetObjectResponse`**

This approach **avoids creating unnecessary copies** of objects in S3.

---

## 🔁 High-Level Request Flow

```
Client
  ↓
S3 Object Lambda Access Point
  ↓
S3 invokes Lambda (event includes getObjectContext)
  ↓
Lambda fetches original object using inputS3Url
  ↓
Lambda transforms the object
  ↓
Lambda calls WriteGetObjectResponse
  ↓
Client receives transformed bytes
```

---

## 🧩 Key Concepts

* **Object Lambda Access Point**
  Acts as the entry point for requests that require transformation.

* **`inputS3Url`**
  A pre-signed URL provided to the Lambda function to fetch the original object.

* **`WriteGetObjectResponse`**
  Core API used by Lambda to send transformed data back to the original requester.

## 🛠️ Steps to Perform

### Step 1: Create an S3 Bucket

* Create an S3 bucket
* Upload a file to the bucket

---

### Step 2: Create an S3 Access Point

* Create an **S3 Access Point**
* Set the **data source** to the bucket created in Step 1
* This access point will act as the **supporting access point** for Object Lambda

---

### Step 3: Create the Lambda Function

* Create a Lambda function to transform the object
* Use:

  * **`inputS3Url`** to fetch the source object
  * **`WriteGetObjectResponse`** to return transformed bytes

> ⚠️ The `WriteGetObjectResponse` call is the **core mechanism** that enables Object Lambda to return transformed data to the client.

---


 below is lambda function code:
 ```python
# transform.py
import boto3
import requests
from botocore.config import Config

# This function capitalizes all text in the original object
def lambda_handler(event, context):
    # event contains getObjectContext when configured for GetObject
    object_context = event["getObjectContext"]

    # presigned URL to fetch original object (supporting access point)
    s3_url = object_context["inputS3Url"]

    # route + token used when returning the transformed object
    request_route = object_context["outputRoute"]
    request_token = object_context["outputToken"]

    # fetch original object via presigned URL (no extra S3 read IAM needed)
    response = requests.get(s3_url)
    response.raise_for_status()

    original_object = response.content.decode("utf-8")

    # transform: uppercase (replace with your logic)
    transformed_object = original_object.upper()

    # write transformed result back to S3 Object Lambda to return to caller
    s3 = boto3.client('s3', config=Config(signature_version='s3v4'))
    s3.write_get_object_response(
        Body=transformed_object,
        RequestRoute=request_route,
        RequestToken=request_token
    )

    # end — return status
    return {'status_code': 200}
```

import boto3
import requests
from botocore.config import Config

def lambda_handler(event, context):
    ctx = event["getObjectContext"]
    s3_url = ctx["inputS3Url"]
    route = ctx["outputRoute"]
    token = ctx["outputToken"]

    # Fetch original object via presigned URL
    original = requests.get(s3_url).content.decode("utf-8")

    # Example transform → convert to uppercase
    transformed = original.upper()

    # Return transformed data to S3 Object Lambda
    s3 = boto3.client("s3", config=Config(signature_version="s3v4"))
    s3.write_get_object_response(
        Body=transformed,
        RequestRoute=route,
        RequestToken=token
    )

    return {"status_code": 200}

Whats working at all??
⭐ LAYER 1 — What normally happens without Object Lambda
When you do:
aws s3api get-object --bucket my-bucket --key tutorial.txt
➡️ The S3 service returns the file exactly as it is stored.
Nothing is changed.

⭐ LAYER 2 — What changes when you use an S3 Object Lambda Access Point
When you use a bucket like this:
arn:aws:s3:us-east-1:918964971928:accesspoint/demo-ap-public
Instead of a normal bucket name…
You are not talking to your S3 bucket directly.
You are talking to:
👉 S3 Object Lambda Access Point → which triggers your Lambda → which fetches the original file → transforms it → sends modified content back.


⭐ LAYER 3 — What the CLI command is doing

STEP 1 — Your CLI sends a GET request
```
aws s3api get-object \
  --bucket arn:aws:s3:us-east-1:918964971928:accesspoint/demo-ap-public \
  --key tutorial.txt \
  output.txt
```

The CLI thinks:
“Get me the file tutorial.txt from that bucket”.
BUT this is NOT a bucket.
This is Object Lambda Access Point.
STEP 2 — S3 forwards the request to Object Lambda

AWS says:
Before I return the file, I must trigger the Lambda associated with this Access Point.
So AWS internally calls your Lambda like:
```
{
  "getObjectContext": {
    "inputS3Url": "presigned-url-to-original-object",
    "outputRoute": "...",
    "outputToken": "..."
  }
}
```
STEP 3 — Your Lambda runs THIS logic
Your Lambda does:
1. Download original file from S3 (through the presigned URL)
2. Transform it In your case → convert text to UPPERCASE.
3. Return transformed content Using:s3.write_get_object_response(...)
AWS then gives this transformed content back to the caller.

STEP 4 — CLI writes the RESULT to output.txt on your laptop
So:
✔ The file in S3 stays the same
✔ The file you GET through the Access Point is transformed
✔ The file saved to output.txt is the transformed version

Example:
Original S3 file:hello animesh, this is object lambda.
Transformed output.txt:HELLO ANIMESH, THIS IS OBJECT LAMBDA.

## **S3 URI vs ARN (Summary Notes)**

### **1) S3 URI format**

* Starts with: `s3://`
* Example:
  `s3://my-bucket/path/to/file.txt`
  `s3://arn:aws:s3:us-east-1:123456789012:accesspoint/my-ap`
* **Used for:** UI, Athena, Spark, EMR, Hadoop
* **Purpose:** Human-readable way to point to an S3 location
* **Not used by:** AWS CLI bucket parameter

👉 Think of it as a **friendly location format**

---

### **2) ARN (Amazon Resource Name) format**

* Starts with: `arn:aws:`
* Example:
  `arn:aws:s3:us-east-1:123456789012:accesspoint/my-ap`
* **Used for:**

  * AWS CLI
  * IAM policies
  * boto3 / APIs
  * S3 Access Points & Object Lambda
* **Purpose:** Official AWS resource identifier

👉 Think of it as the **machine-friendly ID**

---

### **🔥 Most Important Difference**

* **AWS CLI expects the ARN, NOT `s3://`**
* Using `s3://` with Access Points in CLI ❌ fails
* Using ARN ✔ works

---

### **Why AWS shows both**

| Format | Used for             | Meaning              |
| ------ | -------------------- | -------------------- |
| S3 URI | UI & analytics tools | Just a location      |
| ARN    | CLI, IAM, APIs       | Official resource ID |

---

### **Simple Analogy**

* **S3 URI** = Home address
* **ARN** = Government ID

Humans use addresses, systems use IDs.

---

### **Key Rule**

✔ **Always use ARN for Access Points & Object Lambda in CLI/API calls**

---

### **Final One-Line Summary**

* `s3://` → human-readable path
* `arn:aws:` → required for AWS APIs and CLI

Only **ARN** works for Access Points and Object Lambda.
