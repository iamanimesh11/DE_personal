# S3 Replication (SRR + CRR)

S3 replication has two types:
1. SRR -SAME REGION  REPLICATION -Replicate objects from one bucket to another in the same region.
2. CRR- CROSS REGION REPLICATION -Replicate objects from source bucket to another bucket in another AWS region.

⭐ Replication REQUIREMENTS
- versioning must be enabled : both source and  des bucket must have versioning enabled
- s3 must have permission to replicate -aws automatically create IAM role for this.
- only new object are replicatd -Existing objects do NOT replicate unless: “Replicate existing objects” checkbox is enabled.
- Object locks, delete markers, and certain storage classes do NOT replicate

Enable Versioning on Both Buckets
via CLI: 
``` aws s3api put-bucket-versioning  --bucket my-de-lake-replica-animesh11 --versioning-configuration Status=Enabled ```
Go to S3 → Source bucket (my-de-lake-animesh11)
Go to Management → Replication → Create replication rule
Configure:
Rule name: replicate-raw-data
Source bucket: your source
Choose prefix: raw/  (only raw data will replicate)
Destination bucket: my-de-lake-replica-animesh11
IAM role: auto-create
Replicate delete markers: OFF (for now)
Replicate existing objects: OPTIONAL ✔ check it only if you want past files to replicate

⭐ What replicates?
New objects	,New versions, Metadata	✅ Yes
ACLs	🔸 Yes, but optional
Encrypted objects (SSE-S3)	🔸 Yes
Encrypted objects (SSE-KMS)	❗ Only if permissions are correct

⭐ What does not replicates?
glacier object,object lock setting,delete markers,existing object

## ⭐ Two Types of VPC Endpoints

1. Gateway endpoint :
   special route table entry that tell AWS : if trafific is going to s3 or dyanmodb keep it inside as and do not send it to interent.
   so no server,IPS,ENIs,NAT

   example : 1 vpc - 10.0.0.0/16
             1 private subnet - 10.0.1.0/24
             1 ec2 - 10.0.0.1.10
   ec2 wants file:
         s3://bucket_name/file.txt

   ### now without gateway endpoint ###

   1. application request : GET https://s3.amazonaws.com/bucket/file.txt
   2. DNS resolution :dns returns s3.amazonaws.com -> 52.216.XX.XX  ,its public IP
   3. EC2 check route table : 10.0.0.0/16 -> local
                              0.0.0.0/0 ->NAT gateeway
      now decision is :
                dest 52.216.xx.xx
                matches 0.0.0.0/0 SENT TO NAT GATEWAY
   4. NAT GATEWAY
      Rewrite source IP and forward traffic to interent gateway

   5. INTERENT GATEWAY
      traffic enter AWS public edge ,route like normal internet traffic

   6 s3 receive request
     s3 responsd back same way

   ### WITH GATEWAy ENDPOINT ###
   when create endpoint ,AWS :
   -> Create s3 prefix list  ,pl-68a54001 =all s3 IP ranges

       DEST    TARGET
