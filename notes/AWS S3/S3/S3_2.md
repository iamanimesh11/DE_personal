# S3 Replication (SRR + CRR)

S3 replication has two types:
1. SRR -SAME REGION  REPLICATION -Replicate objects from one bucket to another in the same region.
2. CRR- CROSS REGION REPLICATION -Replicate objects from source bucket to another bucket in another AWS region.

⭐ Replication REQUIREMENTS
- versioning must be enabled : both source and  des bucket must have versioning enabled
- s3 must have permission to replicate -aws automatically create IAM role for this.
- only new object are replicatd -Existing objects do NOT replicate unless: “Replicate existing objects” checkbox is enabled.
- Object locks, delete markers, and certain storage classes do NOT replicate

Enable Versioning on Both Buckets
via CLI: 
``` aws s3api put-bucket-versioning  --bucket my-de-lake-replica-animesh11 --versioning-configuration Status=Enabled ```
Go to S3 → Source bucket (my-de-lake-animesh11)
Go to Management → Replication → Create replication rule
Configure:
Rule name: replicate-raw-data
Source bucket: your source
Choose prefix: raw/  (only raw data will replicate)
Destination bucket: my-de-lake-replica-animesh11
IAM role: auto-create
Replicate delete markers: OFF (for now)
Replicate existing objects: OPTIONAL ✔ check it only if you want past files to replicate

# S3 Analytics — Storage Class Analysis + S3 Inventory + Access Logs #

## S3 Storage Class Analysis
basically aws analyzes hw frquently objects are accessed in bucket  and recommend:
which object should be moved to standard-IA
when to use intelligent tiering
when to apply for lifecycle rules
Think of it like S3 saying:

“Bro, these objects are not being accessed often — move them to IA to save money.”
]Key Points for Exam
Works on prefix or tag level,Generates insights after 24–48 hours,Used to create lifecycle policies,Cannot analyze objects in Glacier,No extra charge (free)


🪜 How to Enable (Console)
Open your bucket → Management tab
Scroll to “Storage Class Analysis”
Click Create analytics configuration
Set prefix = raw/
Save
After 2 days, AWS will recommend:
Move raw/* to IA after 30 days
Or switch to Intelligent-Tiering
💡 Exam trick: Storage Class Analysis is for observing access → NOT automatic.
Lifecycle moves the data automatically.

## S3 inventory ((Audit tool for listing objects)

🧠 What is it?
S3 Inventory creates a daily or weekly CSV report that lists EVERY object in your bucket and its metadata.

It’s used when:
Your bucket has millions of objects
ListObjects becomes too expensive
You need audits for compliance
The report includes:
Object key
Size
Last modified
Storage class
Encryption status

Stored in another S3 bucket.

🧩 Key Exam Facts
Output format: CSV or ORC
Frequency: Daily or Weekly
MUST choose a destination bucket
Used instead of LIST for huge buckets
Used for compliance & audits

🪜 How to Enable
S3 → your bucket - Management → Inventory - Create inventory- Destination bucket: my-de-lake-animesh11 -Daily-Output format: CSV

## ⭐ Topic 4C: S3 Access Logs (logs of every request made to your bucket)

🧠 What is it?
S3 can log:
Who accessed your bucket
What operations they performed
IP address, time, userAgent
Useful for:
Troubleshooting access-denied errors
Auditing security
Investigating unauthorized access
Logs are stored in another bucket

🧩 Key Exam Points
Access logs are NOT real-time
Stored in another bucket (cannot log to itself!)
Use CloudTrail for API-level logs
Use S3 Access Logs for request-level logs
Can generate LOTS of logs (cost scaling)

🪜 How to Enable
Bucket → Properties
Server access logging
Choose a different bucket as destination
Save

🎯 Short Summary (Exam Must-Know)
Feature	Purpose	Key Exam Fact
Storage Class Analysis	Analyze access patterns	Used to help create lifecycle rules
S3 Inventory	CSV report of all objects	Great for large buckets, auditing
Access Logs	Request logging	Cannot log into same bucket
